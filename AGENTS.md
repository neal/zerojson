# Working on zerojson

Before planning or changing code, read `DEVELOPMENT_PLAN.md` and check the
current branch and working tree. Resume its next incomplete gate; do not
replace it with another open-ended review or fuzzing round.

Keep the plan current when a gate completes, evidence changes a decision,
or work stops. Record what actually ran, the candidate revision, remaining
limitations, and the concrete next action. If new findings change the plan,
explain the change rather than silently starting a different effort.

The plan does not authorize deployment, pushing, paid infrastructure, or
changes to downstream applications. Preserve unrelated work.
