# Coverage boundaries

Passing fuzz executions count exercised inputs, not covered Go type shapes
or verified invariants. Use this checklist when extending the test framework.

| Layer | What it checks | Boundary to keep visible |
| --- | --- | --- |
| Generated byte fuzzers | Decode/encode comparisons on generated types | Opaque codecs and documented divergences narrow comparisons; generation and oracle dispatch share classification code |
| Type-shape and method-set fixtures | Compilation and behavior of enumerated cases | Coverage of individual dimensions is not their full cross-product |
| Stateful publication campaign | Final values, retained references, alias identity, callback order, callback-time snapshots, input integrity | Six integer-leaf layouts, bounded operation streams; arbitrary callback programs and cross-decoder reentrancy are not enumerated |
| Independent challenge | Typed observations without campaign helpers or projection | A small set of explicit scenarios, not a universal oracle |
| Mutation catalog | Sensitivity to selected compile-valid defects | A catalog kill rate is not coverage of unknown defect classes; baseline detectors must pass first |
| Resource tests | Selected allocation/scaling/depth boundaries | Not a universal memory ceiling; pooled storage retains its high-water mark |

## Observation rules

- Give each decoder its own input bytes; compare them with the original even
  when decoding fails. Otherwise one decoder can contaminate the oracle's input.
- Retain references to detect later writes, and separately snapshot values at
  callback boundaries. A retained pointer is not a historical value snapshot.
- Calibrate observers with equal-valued distinct pointers, later mutation of
  maps/slices, nil versus empty containers, and intermediate writes.
- Do not compare failed partial targets as though stdlib compatibility were
  promised. Test applicable safety properties and recovery separately.
- Do not carry pooled-output references past the documented invalidation point
  unless the references belong to independently supplied caller storage.
- A generation mode is not proof that an ordered path executed: custom-method
  dispatch disables speculation. Use path-specific tests for path coverage.

## Callback publication regression

`TestCallbackSeesSliceProgress` pins callback-visible publication. Before
stdlib container delegation, callbacks decoding a slice of custom JSON
values from `{"Values":[1,2]}` saw enclosing slice lengths
`[1,2]` with stdlib and `[0,0]` with zerojson, although final values agreed.
The independent fixture reproduced this on Go 1.26.5 and 1.27.0 across
copy/borrow and pooled/non-pooled entry points. Both generation configurations
reproduced it; custom dispatch itself uses the fallback path. The regression
now passes through stdlib delegation for containers of JSON/Text values.

The publication campaign now captures enclosing values at custom-leaf and
hook callbacks, exposing this category on existing deterministic seeds.
Do not exempt those snapshots merely to restore a green gate.

## Next expansions

1. Extend publication checks to interactions with explicitly registered readers.
   Ordinary containers with custom JSON/Text fields now delegate to stdlib,
   including generated structs, pointer elements and roots. Registered reader
   and marker contracts remain generated paths and need separate coverage.
2. Add an explicit interaction inventory for embedded fields, custom methods,
   duplicate keys, and pre-existing aliases. Declare excluded combinations;
   do not describe random schemas as exhaustive coverage.
3. Add isolated-process resource campaigns across generated shapes, including
   large-to-small pooled reuse. Separate expected retained capacity from leaks
   and avoid noisy wall-clock thresholds in ordinary tests.
